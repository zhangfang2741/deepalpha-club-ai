# 市场雷达：自上而下的主线 + 只呈现事实

日期：2026-10-01
范围：iOS 缠论 App「雷达」「自选」Tab + 后端 signal_radar / watchlist
前置：`2026-10-01-market-macro-sector-design.md`（宏观 / 行业数据）
设计稿：claude.ai 画布「缠论 App 主线改版」（雷达扇区版、环境 / 行业 / 当日信号 / 气泡四个面板、自选）

## 背景

App 已经有宏观、情绪、行业、个股四层数据，但它们并排摆着，彼此不作用，用户得自己拼出结论：

- 顶部「宏观 / 情绪」两格只是信息，不影响下面显示什么；行业筛选条是过滤器，不是判断；
- 点气泡直接进详情页，进去之后看不到「它属于哪个行业、行业强不强、大盘什么状态」；
- 一屏里有市场分段、两格、指数切换、行业条、气泡（6 种编码）、排雷说明、图例、日期轨、免责，没有主次；
- 雷达「前 10」是综合分（类型 + 强弱 + 新鲜度 + 共振）排出来的，再叠一层基本面排雷——本质是在替用户挑股票。

产品定位：**不做推荐，只把事实按自上而下的顺序摆给用户**（环境 → 行业 → 个股），用户自己判断。

## 已确认的决定

1. **雷达画成扇区**：角度 = 行业（按所选日相对大盘强弱，第 1 名正上方，之后右上 / 左上依次往下，越靠上越强），
   半径 = 时间（越新越靠中心）。没有行业统计（港股 / A 股 / 自选）时退回同心环。
2. **顶部三格**：环境（大盘状态 + 情绪）/ 行业（所选日领先行业）/ 当日信号（在场信号数、买卖数）。
3. **解释留在雷达页**：点格子、扇区标签、气泡都弹底部面板；气泡面板列四层事实（大盘 / 行业 / 结构 / 基本面），
   「查看K线与结构详情」才进详情页。**详情页保持现状**。
4. **只呈现事实**：去掉综合分前 10、类型保底、共振加分、基本面排雷，也不做「与环境一致 / 相反」的判断或调暗。
5. **自选页同一套语言**：环境横幅 + 按「近 5 日有信号 / 暂无新信号」分组 + 每行行业圆点、结构阶段、基本面等级、在场信号。
6. 「分析」「学习」Tab 合并 / 收起**本期不做**（设计稿里画了三 Tab，留待后续单独讨论）。

## 雷达上显示哪些信号（取舍规则）

保留（都是信号本身的定义，不是挑选）：

- 缠论宽松口径（`signal_policy`）判出的一 / 二 / 三类买卖点；
- 收盘价跌破买点价位（卖点：涨破）当天起退场；
- 出现后 5 个交易日内在场；一周前的展示日不显示未确认信号。

去掉：综合分排序与前 N 截取（`radar_score` / `_select_top_n` / `rerank_with_resonance` 只留给旧版 App）、
基本面排雷（`MINE_RULES` 删除）。评级只标注。

排序只用事实：信号按出现日期从新到旧（同日按代码）；扇区按行业相对大盘强弱。

## 后端

- `service._assemble` / `_assemble_demo`：每天存**全部在场信号**，`order_by_time` 排序；`attach_grades` 只标注。
- 接口 `GET /signal-radar`、`/signal-radar/demo` 新增 `scope`：`all`（新版 App，全部）/ `top`（默认，旧版 App，
  `legacy_view` 按旧综合分现截前 10）。旧版 App 的雷达布局按 10 个气泡设计，不能直接塞全部信号。
- 次级别（30 分钟）补算：`sub_level_targets` = 当天新出现的信号 + 旧版前 N 候选池，封顶 30 只（美股 30 分钟
  要分段拉 FMP、每只约 3 次且不经 `fmp_budget`；标普 500 实测一天约 27 个当日新信号）。盘中 30 分钟刷新同一批。
- 快照写 Redis 前 zlib 压缩（`pack_snapshot` / `unpack_snapshot`，兼容旧明文）：标普 500 实测明文约 760KB、压缩后约 19KB。
- 自选雷达也打行业标签；自选列表 `GET /watchlist` 每条带 `sector`（仅美股）。
- 升缓存键 `_mode_ns` 为 `…:quant_mark2:all1`，旧快照（排雷 + 前 N）自动失效。

## iOS

- `SectorRadarLayout`（纯函数，`ios/Tests/run-sector-radar-tests.sh`）：扇区中线角（名次 → 从上往下、同高先右后左）；
  名额 `quotas`：每个行业先 1 个，其余按信号数成比例（最高平均数法），总上限 36、单行业 6，取最新的；
  摆位 `pack`：每个扇区铺候选网格，第一轮先放可用位置最少的扇区、之后按强弱轮流，圆心必须落在自己扇区内、
  不压扇区标签 / 指数切换器、重叠 ≤15%，放不下的计入标签「+N」；同一扇区里越靠里越新。
  有信号的行业才成扇区，没有行业标签的归「其它」排最后。扇区标签只写行业名 +「+N」。
  **不要**改回「按时间半径摆好再碰撞推开」：一天的信号大多是当日 / 前一日的，会全挤在圆心、推开后跑出自己的扇区
  （真实数据回放：底部四个行业的扇区里一个气泡都没有）。
- 同心环模式最多画最新 14 个，其余「另有 N 个 · 查看全部」打开信号列表。
- 面板（`RadarPanels.swift`）：
  - 环境 = `MacroDetailSheet` + 情绪卡（当前 / 一周前 / 一月前 + 60 日走势，「完整走势」打开原恐慌指数弹层）；
  - 行业 = 行业切换条 + 状态 / 名次 / 以 0 为中线的强弱条 + 该行业全部在场信号 + 细分行业 / 全部行业强弱；
  - 当日信号 = 全部在场信号，可按买卖、一二三类筛；
  - 气泡 = 四层事实；基本面行在美股按需拉一次基本面研究（综合 + 护城河 + 各维度等级）。
  行业 / 当日信号 / 气泡面板与气泡同一道免责声明门槛；免费用户仍只能看示例日。
- 去掉行业筛选条、行业池请求、排雷统计行；请求带 `scope=all`。
- 自选：`WatchlistViewModel.loadFacts` 拉各市场大盘状态、美股行业强弱、各市场自选雷达最新一天的在场信号；
  信号与结构状态同一道档位门槛（高级版全部、示例股、免费看的那一支），看不到的显示锁。

## 文案

只描述事实：不出现「推荐 / 一致 / 同向 / 顺风」等判断词；各面板底部一句「事实陈列，不构成投资建议」。

## 测试

- 后端：全部在场信号不截取（含示例日、自选）、旧版 `scope=top` 仍为前 10、`scope` 非法值 422、
  `order_by_time`、`sub_level_targets` 优先当日并封顶、原排雷对象照常在场、缓存键版本、自选雷达与自选列表的行业标签。
- iOS：`SectorRadarLayoutTests`（名次位置、名额、取最新、「其它」最后、时间半径）；
  `run-radar-quant-tests.sh` 解码兼容。SwiftUI 部分需在 Xcode / 真机验证（`ios/Tests/build-check.sh`）。

## 真实数据回放（2026-10-01）

用 Yahoo 拉标普 500 全部 503 只两年日线，走同一套 analyzer + `build_days`（30 个展示日）：

- 每天在场信号 36~98 个（中位 70），最新一天 98 个、11 个行业，其中当日新出现 27 个；
- 扇区雷达（`pack`，气泡最小 44pt）：366×330 画 23 个、11 个行业都有；402×380 画 28 个；351×280 画 15 个；
  画布压到最小高度 240 时有 1~2 个窄扇区放不下（标签仍显示「+N」、可点开）。

## 风险 / 待验证

- 小屏（iPhone SE）与 12 个行业都出现时扇区较窄，需真机看标签与气泡是否拥挤。
- 自选页首次打开会为自选雷达触发一次后台扫描（自选股票少，几秒内完成），期间按市场分组展示。
